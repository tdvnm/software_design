From setup to planning

Four participants: the Admin who sets the database up, the User planning in the browser, the Server and the Database. Solid arrows are requests, dashed arrows are replies.

Reading the diagram

  • Setup: the administrator runs the database scripts from the command line. This is separate from handling browser requests.
  • Planning: the browser downloads the page, its assets and the course CSV. Search, details, add/remove and credit totals then run locally.
  • Health check: a separate request to /api/health runs SELECT 1 against SQLite. The planner does not request it automatically.
  • Persistence: the active plan stays in memory and resets on reload. The plan API routes shown at the bottom are proposed future work.
