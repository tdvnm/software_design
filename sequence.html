From setup to planning

Four participants: the Student, the Browser, the Server and the Database. The browser handles plan edits and local saving.

Reading the diagram

  • Setup: the administrator runs the database scripts from the command line. This is separate from handling browser requests.
  • Planning: the browser downloads the page, its assets and course JSON through the API. Search, details, add/remove and credit totals then run locally.
  • Health check: a separate request to /api/health runs SELECT 1 against SQLite. The planner does not request it automatically.
  • Persistence: the active plan saves in localStorage and restores on reload. Export/import uses JSON files. Server plan routes are implemented but are not called by this interface.
